# Security Policy

## Scope

Nexora Institute of Computing publishes educational content: notes, labs, assignments, and project briefs. It does not run production services or store user data.

## What Counts as a Security Issue Here

- A lab's starter code or tests containing an actual vulnerability (e.g. SQL injection examples that could be copied unsafely, hardcoded real credentials)
- Malicious links or downloads in any subject repository
- Exposed secrets or personal information accidentally committed
- Supply-chain concerns in any `package.json`, `requirements.txt`, or similar dependency files

## What Does NOT Count

- Theoretical vulnerabilities *discussed as part of a lesson* (e.g. an intentionally broken sample in a security lab) — these are educational.
- Outdated library versions in a lab's example code — open a normal content issue instead.

## How to Report

Please **do not open a public issue** for a real security concern. Instead, use GitHub's private vulnerability reporting:

1. Go to the affected repository on GitHub.
2. Click **Security** → **Report a vulnerability**.
3. Describe the issue and where it appears.

We aim to respond within 7 days and to publish a fix or clarification within 30 days.
